## 3. Methodology（方法論）

本節では、Scenicプログラミング言語と対象化された検索メカニズムの適用を通じた、安全臨界シナリオ生成のためのLLMエージェントChatSceneの接近法を詳述する。鍵となる用語の定義を含む簡潔な動機付けから始める。次に検索データベースの構築に焦点を当て、続いて人間またはLLM由来の安全臨界シナリオのテキスト記述をScenicコードへ変換する過程を説明する。具体的には、まず元のテキスト記述を各構成要素（例：敵対的行動）に対する下位記述へ分解する。次にこれらの構成要素をベクトルへ符号化し、検索データベースから対応するスニペットを検索する鍵とする。これらのスニペットは組み立てられて包括的なScenicスクリプトを形成し、CARLA環境内でシミュレーションを実行するために実行される。

### 3.1 Motivation and Notations（動機と記法）

Scenicプログラミング言語はCARLAにおけるシミュレーション描画にきわめて有効で柔軟である。当然の問いが生じる。「ChatGPTのような大規模言語モデルに、安全臨界シナリオの記述に基づき対応するScenicコードを直接書かせることができるか」。この接近法は有望に見えるが、コンパイル不能なコードの生成や、コードベースに存在しないAPIの使用のような問題をしばしば引き起こす。これはLLM学習用のScenic例の不足と、コード生成の複雑さ・広範さによるもので、モデルの幻覚を誘発しうる。

しかしScenicコードを検討すると、Figure 3に示すように概して4構成要素に分割できる。(1) 典型的には固定の既定マップ・モデル設定。(2) 周囲車両の敵対的行動の定義。(3) 自車の出現点にも影響する道路幾何。(4) 自車に対する周囲車両の相対出現位置。なお自車は強化学習で学習したモデルにより制御されるため、その行動を定義する必要はない。

これに基づき、より効率的な方法を提案する。最後の3構成要素について、対応する記述付きコードスニペットのデータベースを収集する。この接近法は幻覚を低減し、これらスニペットの完全なScenicコードへの柔軟な組立てを可能にするはずである。評価時には、「自車は直線道路を走行しており、自車の接近に伴い前方の車両が突然制動する」のような入力記述に対し、LLMエージェントはまず、例えば行動構成要素に対する「Behavior: 自車の接近に伴い敵対的車両が突然制動する」のように、各構成要素に対する下位記述へ分解できる。次にエージェントは対応する検索を行い、関連コードスニペットを組み立てる。

Route（ルート）。「route」は本質的にウェイポイントの系列であり、各々は車両がその軌跡中に通過すべき特定位置を示す。CARLA模擬環境では、このルートは始点と終点の両方を含む自車両の事前決定経路を表す。

Base Scenario（基盤シナリオ）。「base scenario」は高水準の敵対的運転状況を概念化するために用いられる。「自車両前方の直線障害物」のように、障害物の正体や敵対的行動の具体的内容には立ち入らない抽象的枠組みを提供する。この抽象化により多様な運転課題の一般化された分類が可能になる。

Scenario（シナリオ）。対照的に「scenario」は、障害物とその具体的行動に関する詳細属性を吹き込むことで「base scenario」の上に構築される。例えば前出の「自車両は直線道路を走行しており、自車両の接近に伴い前方の車両が突然制動する」は、上記の基盤シナリオから導出されたシナリオであり、敵対的状況の具体的動態を導入して初期記述を豊かにしている。

Scene（シーン）。「scene」は「scenario」の実用的実例化を表し、敵対的事象の具体的内容を詳述する。これには自車両のルート、周囲敵対車両の特性（例：車種）、環境文脈（例：建物や交通信号）が含まれる。さらにエージェントの位置・速度・初期配置のようなパラメータを指定する。なおScenicは実際には確率的プログラミング言語として振る舞う。対応するCARLA模擬を実行する前にADV SPEEDのようなパラメータを標本化する。この能力により、単一Scenicスクリプトから、速度を所定範囲内で変えることで同一シナリオに対する多様な distinct シーンを生成できる。

### 3.2 Construction of the Retrieval Database（検索データベースの構築）

本節ではScenicコードスニペットの体系的収集・統合を強調し、検索データベース構築の方法論を詳述する。

Collection of Snippets（スニペット収集）。スニペット収集過程はScenicリポジトリの初期例の調達から始まる。直線道路・交差点のような多様な敵対的行動・幾何構成を覆うこれらの例は、記述・スニペット対へ手動で分解される。この初期結合データセットを用い、LLMのfew-shot学習により多様なスニペットを生成する。各新規生成スニペットは、Scenicの多様なAPI文脈における適合性・コンパイル可能性について厳密に評価・手動修正される。本研究では一貫してGPT-4を用いてスニペットを収集する。

Database Construction and Query Optimization（データベース構築と照会最適化）。記述・スニペット対ごとに、GPT-4に各記述の異なる言い換えをさらに生成させ、元のスニペットは各対で維持する。この接近法は検索精度の向上を意図する。記述はSentence-T5を用いて符号化され、データベース構築と照会過程はfaissにより容易化される。異なる構成要素、すなわち敵対的行動・道路幾何・相対出現位置のデータベースを独立に構築・管理する。

### 3.3 Safety-Critical Scenario Generation（安全臨界シナリオ生成）

i. Generating Descriptions（記述生成）。検索データベース完成後、LLMエージェントChatSceneはまず多様な安全臨界シナリオ記述を生成できる。

ii. Extracting Component Descriptions（構成要素記述の抽出）。整理された下位記述は「Behavior: ... / Geometry: ... / Spawn Position: ...」として整形される。したがってエージェントは正規表現を用いて各構成要素の対応記述を効率的に抽出できる。

iii. Retrieving Scenic Code Snippets（Scenicコードスニペットの検索）。記述抽出後、エージェントはSentence-T5モデルを用いてそれらを符号化する。埋め込みは各構成要素の関連Scenicコードスニペット検索の鍵となる。

iv. Scenario Rendering and Evaluation（シナリオ描画と評価）。Scenicコードスニペットは完全スクリプトへ組み立てられ、CARLAで模擬を実行するために実行される。ADV SPEEDを[0,10]間、ADV DISTANCEを[0,20]間のように、異なるパラメータ値が標本化され、複数シーンが収集される。各フレームの位置・速度・加速度・衝突情報を含む包括的詳細が収集される。

### Metrics（評価指標）

Safebenchにおける評価は3範疇を含む。Safety level（衝突率と交通信号遵守を含む）、Functionality level（ルート遵守と完走）、Etiquette level（運転の円滑さと車線規律）。われわれの焦点は主として衝突率と複合全体的スコア（OS）にあり、後者は全指標を集約する。各算法が生成したシーン多様性を測定するために平均変位誤差（ADE）も利用する。具体的には、同一シナリオに生成された各シーン対の軌跡間で、各対応時点の敵対物の位置間のユークリッド距離の平均の平均として計算される。

### 4.2 Safety-Critical Scenarios Generation（安全臨界シナリオ生成）

特筆すべきことに、ChatSceneは既存最良ベースラインに対する衝突率の15%増加により、安全臨界シナリオ生成を有意に増強する。全体的性能に関して、エージェントは全体的スコアの有意な相対低減を達成し、先行ベースラインに対する16%に相当する。この低減は、われわれのシナリオが提示する複雑さ・課題の高まりを裏付ける。
